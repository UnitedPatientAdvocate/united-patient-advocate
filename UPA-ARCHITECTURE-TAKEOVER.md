# UPA Architecture Takeover

## Purpose
This document is the approved source of truth for the UPA architecture takeover. Its job is to define the minimum complete structure required to duplicate the current UPA system into a clean, high-conversion medical billing workflow without adding unnecessary complexity.

## Core Rules
- One findings system
- One action plan
- One timeline
- One case score
- One letter library
- One source of truth

## The 5 Buckets

### 1. SEE WHAT'S WRONG
These assets help the buyer understand the problem.
- Billing Findings Report
- EOB Decoder
- Denial Reason Decoder
- Financial Review Summary

### 2. TAKE ACTION
These assets help the buyer do something immediately.
- Appeal Letter Kit
- Dispute Letter Templates
- Itemized Bill Request Letter
- Insurance Call Scripts
- Provider Contact Guide
- Escalation Playbook

### 3. STAY ON TRACK
These assets keep the buyer moving through the case.
- Appeal Deadline Tracker
- Evidence Checklist
- Call Log Worksheet
- Case Action Plan
- Case Progress Tracker

### 4. FAST START
These assets reduce overwhelm and create immediate confidence.
- Quick Start Guide
- Sample Appeal Packet
- Peace of Mind Checklist

### 5. WORKSPACE
These assets give the buyer one place to manage everything.
- Case Workspace
- Downloads
- Packet
- Timeline

## Implementation Notes
- Build from the core outward.
- Reuse the same structure across verticals.
- Do not add new systems unless they directly improve revenue or trust.
- Keep the source of truth in one place.
- Every asset should support one of the 5 buckets.
- Every page should show the buyer exactly what they receive.

## Success Criteria
The architecture takeover is complete when:
- the 5 buckets are present
- the approved 7 tools are present
- the visual asset inventory is present
- the build order is present
- the document can be used as the single reference for execution
